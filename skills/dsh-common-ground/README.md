## 副本为什么是"脱敏"的

原工程名、盘符与本机库路径**只在本机有意义**：技能复制到别的设备后，
它们**既打不开、又会误导**（读者会以为这些名字在那边也能索引到）。所以副本里一律**代称化**：

| 原件里 | 副本里 |
|---|---|
| 原工程的中文专名 | **`某工程`** |
| 原工程名 + `旧案` 复合词 | **`旧案`**（或 `旧案\开发室\` → `旧案\`） |
| `工程名\` 这类带根名的路径前缀 | **去掉前缀**，只留 `docs\…`、`证据\…` |
| 本机库路径（源目录 / 技能目录） | `源目录\`、`本技能\` |
| 工程内文件名（如"××拟案.md"） | 保留结构、代称化文件名（如 `裁定案.md`） |

**日期与裁定编号保留**（如 `2026-09-22`、`A-28`）——它们是"这条规矩有代价"的凭据，
不指向具体项目，也无法用来索引任何东西。

> ⚠ **脱敏是一条固定规则的单向变换**，由**源项目侧的生成脚本**产出（脚本按定义含真名，**故不进技能包**）。
> 所以副本**不是第二份事实源**，而是**生成物**：它可以被**复算**。
> **手工改副本 = 制造第二份会漂移的事实**——发现副本与脚本输出不一致，一律按缺陷处理。

## 五道核对（每条自带：覆盖 · 不覆盖 · 证据行 · 复跑命令）

### 核对一：安装版与技能源**逐字相同**

```powershell
$lib  = '<技能源目录>'                                    # 例：<源项目>\skill\dsh-common-ground
$inst = Join-Path $env:USERPROFILE '.agents\skills\dsh-common-ground'
$libFiles  = Get-ChildItem $lib  -Recurse -File
$instFiles = Get-ChildItem $inst -Recurse -File
$bad = foreach ($f in $instFiles) {
  $rel = $f.FullName.Substring($inst.Length + 1); $ref = Join-Path $lib $rel
  if (-not (Test-Path -LiteralPath $ref -PathType Leaf)) { 'MISSING IN SOURCE: ' + $rel }
  elseif ((Get-FileHash -LiteralPath $f.FullName).Hash -ne (Get-FileHash -LiteralPath $ref).Hash) { 'DIFF: ' + $rel } }
$missing = foreach ($f in $libFiles) {
  $rel = $f.FullName.Substring($lib.Length + 1)
  if (-not (Test-Path -LiteralPath (Join-Path $inst $rel) -PathType Leaf)) { 'MISSING IN INSTALL: ' + $rel } }
'证据：技能源 ' + $libFiles.Count + ' 个文件；安装版 ' + $instFiles.Count + ' 个文件'
if ($bad) { $bad; exit 1 } elseif ($missing) { $missing; exit 1 }
else { '核对一 OK: ' + $instFiles.Count + ' files identical to skill source' }
```

- **覆盖**：安装副本与技能源**逐字节相同**，**文件集合也一致**（多／少／缺都报）。
- **不覆盖**：**不判技能能否被 DSH 正确加载**（那取决于目录约定与 frontmatter，不是字节问题）——**本机加载已有直接证据（见文末"五道合起来也不覆盖什么"第 6 条补记），换机器仍未验**；也不判内容对不对。
- **注意**：`-PathType Leaf` 是必要的——不带它时 `Test-Path` 对**目录**也返回真，缺文件会被误判成"存在"。

### 核对二：副本 = **重跑生成脚本**的输出（逐字）

```powershell
$gen = '<源项目>\构建\脱敏生成副本.ps1'
$res = '<技能源目录>\resources'
$tmp = Join-Path $env:TEMP ('desens_' + [guid]::NewGuid().ToString('N'))
& $gen -OutDir $tmp -PairDir $res                       # 非破坏性：只生成到临时目录
$bad = foreach ($f in (Get-ChildItem $res -Filter *.md -File | Where-Object { $_.Name -notlike '*.en.md' })) {
  $ref = Join-Path $tmp $f.Name
  if (-not (Test-Path -LiteralPath $ref -PathType Leaf)) { 'MISSING IN GENERATED: ' + $f.Name }
  elseif ((Get-FileHash -LiteralPath $f.FullName).Hash -ne (Get-FileHash -LiteralPath $ref).Hash) { 'DIFF: ' + $f.Name } }
'证据：已发布副本 ' + (Get-ChildItem $res -Filter *.md -File | Where-Object { $_.Name -notlike '*.en.md' }).Count + ' 篇；重跑生成 ' + (Get-ChildItem $tmp -Filter *.md -File).Count + ' 篇'
Remove-Item $tmp -Recurse -Force
if ($bad) { $bad; exit 1 } else { '核对二 OK: 副本与生成脚本输出逐字相同（可复算）' }
```

- **为什么用 `-PairDir $res`**：语言切换行只在"该篇有英文兄弟"时才插，而这个判定必须看**技能源目录**，不能看临时输出目录——
  否则临时目录里没有 `.en.md`，就会少插一行，把"副本被手工改过"误报出来（**本轮真踩到过一次**）。
- **为什么排除 `*.en.md`**：**英文译本是人工译的，不是生成件**，不属于"副本 = 脚本输出"这条判据；它由 `核对译本` 单独管。

- **覆盖**：副本**就是**当前源 ＋ 当前脱敏规则的产物**（等价于"副本没被手工改过、也没落后于源"）。
- **不覆盖**：**不判脱敏规则选得对不对**（哪些词该代称化是人定的）；**不判源内容对不对**。
- **前提**：脚本与源都在本机。**换工程后这条没有对象**——那时副本与源的关系由你的项目自己定。

### 核对三：**零残留**（副本里不得再有可索引原工程的词）

```powershell
$res = '<技能源目录>\resources'
# 禁用词表在生成脚本里（脚本含真名，故不进技能包）；这里给它一个**独立**的复本做交叉检查
$forbidden = @('<原工程专名>', '<原工程名的拼音/英文标识>', '<原工程根目录名>')
$hit = foreach ($f in (Get-ChildItem $res -Filter *.md -File)) {
  $t = Get-Content -LiteralPath $f.FullName -Raw -Encoding UTF8
  foreach ($w in $forbidden) { if ($t -like ('*' + $w + '*')) { $f.Name + ' 含「' + $w + '」' } } }
'证据：扫 ' + (Get-ChildItem $res -Filter *.md -File).Count + ' 篇副本；禁用词 ' + $forbidden.Count + ' 个'
if ($hit) { 'RESIDUE:'; $hit | Select-Object -Unique; exit 1 } else { '核对三 OK: 零残留' }
```

- **覆盖**：副本里**不出现**任何可用于索引原工程的词（工程名、其英文标识、根目录名）。
- **不覆盖**：**不判"还有没有别的可索引信息"**（比如你没想到要加进禁用词表的词）；
  也不判日期、编号、工程内文件名——**那些按约定保留**。
- **诚实说明**：这条判据的强度**等于禁用词表**。表是手写的，就一定有漏——
  所以它只保证"**已知的**外部词不残留"，**不承诺"脱敏彻底"**（[05 §三](resources/05-验证与假通过.md) 判据七条硬要求）。

### 核对四：内部链接**文件级**可达

```powershell
$root  = '<技能源目录>'      # 也可指向整个项目树
$floor = 20                  # 防呆下限，不是覆盖率指标；按文档规模重定
$files = Get-ChildItem $root -Recurse -Filter *.md -File
$links = foreach ($f in $files) {
  $t = Get-Content -LiteralPath $f.FullName -Raw -Encoding UTF8     # ← 必须带 -Encoding UTF8
  $t = [regex]::Replace($t, '(?s)```.*?```', '')                    # fenced 代码块里的不是活链接
  $t = [regex]::Replace($t, '`[^`\r\n]*`', '')                      # 行内代码里的同样不是
  [regex]::Matches($t, '\]\(([^)#]+\.md)(#[^)]*)?\)') | ForEach-Object {
    [pscustomobject]@{ From = $f.FullName; Target = $_.Groups[1].Value } } }
$links  = $links | Where-Object { $_.Target -notmatch '^[a-z]+://' }
$broken = foreach ($l in $links) {
  if (-not (Test-Path -LiteralPath (Join-Path (Split-Path $l.From -Parent) $l.Target) -PathType Leaf)) {
    $l.From.Replace($root, '') + '  ->  ' + $l.Target } }
'证据：扫 ' + $files.Count + ' 个 .md，提取 ' + $links.Count + ' 条内部链接'
if ($links.Count -lt $floor) { 'SCAN FLOOR FAILED: 只找到 ' + $links.Count + ' 条（扫不到＝没查）'; exit 1 }
elseif ($broken) { 'BROKEN LINKS:'; $broken | Select-Object -Unique; exit 1 }
else { '核对四 OK: ' + $links.Count + ' internal links, all resolvable' }
```

- **覆盖**：内部链接的**文件级**可达。
- **不覆盖**：**锚点级**（`§x.y` 是否真的存在）、外链、非 `.md` 目标、**文字指针**、链接两侧说法是否一致。
- **只查"活链接"**：fenced 代码块与行内代码里的**一律跳过**——文档里为举例写出 `[](不存在的文件.md)` 是**故意的**
  （这条规则本身就是一次**假阳性**逼出来的）。
- **`$floor` 是防呆下限**（"扫不到"与"扫到 0 条断链"必须能区分），**不是覆盖率指标**。
- **链接卫生**：技能包内部相对链接是安全的（**整包一起搬**）；但**文档被单独复制到别处**时，
  跨目录的 `../` 相对链接**在源位置能通、在副本位置必然断**——那种场景只链同目录兄弟文件，跨目录写文字指针。

### 核对译本：双语兄弟对（`<篇名>.md` / `<篇名>.en.md` / `<篇名>.i18n.yaml`）

```powershell
& '<源项目>\构建\核对译本.ps1'          # 只查、不改
& '<源项目>\构建\核对译本.ps1' -Write  # 人确认"两边此刻说的一样"后，记录两侧内容哈希
```

- **对象**：技能源目录下**每一对**（以 `*.en.md` 为准发现：有英文件就必须有中文件与记录；记录多出或少掉都报）。
- **覆盖**：完整性＋**一致性记录**（两侧 sha256 与当前内容一致）· **语言切换行**（两侧 H1 之后）·
  **结构签名**（标题深度序列／列表条目数／表格行列数／围栏数与 info string／链接条数）·
  **英文侧链接语种规则**（该篇有英文兄弟时必须指 `.en.md`）· **英文侧中文残留**（白名单：术语／行内代码／链接目标／切换行）。
- **不覆盖**：**译文内容对不对**——结构签名与哈希**都不判语义**，只能人读；
  也不覆盖**列表分布**（只按种类合计条目数）、**围栏内容是否逐字相同**（这里围栏里装的是文案而非代码）、
  **frontmatter**（英译**故意不带** `name`／`description`，否则会被 loader 当成第二个技能条目）。
- **双向自证**：记录未建／内容改了没重新记录 ⇒ **红**；删掉英文侧一个标题后**重新记录**（哈希已对上）⇒ 结构签名**仍独立报红**；恢复 ⇒ 绿。
  门本轮当场抓到三处：译文把中文的**全角 `＋`** 译成行首 `+ `（被算成一个列表项）、
  `SKILL.en.md` 该指英文译本却指向中文件、以及**门自己的假红**（切换行里的 `[中文](SKILL.md)` 被链接语种规则误判 ⇒ 按定义跳过切换行）。
  **假红不修，这道门会天天红，然后被人关掉**——那比没有门更糟。
- **L3（八篇正文）落地时又抓到五类，每类都按"类"修**：① 英文侧**自己加了链接**（链接条数是结构签名的一项）⇒ 去掉链接标记只留文字；
  ② 行内代码里的**出处指针**被译成阿拉伯数字（`docs/02 §一`→`§1`）——那是**引中文原文的定位符，改了就对不上原文** ⇒ 逐字还原，并把"行内代码逐字保留／正文转阿拉伯数字"写进规范；
  ③ **全角 `＋` 在行首**被译成 `+ ` ⇒ 被当成列表项（**我自己在 L1/L2 踩过同一坑**）⇒ 按类统一扫全部英文侧；
  ④ 生成脚本的切换行依赖"英文兄弟是否存在"，**晚到的三篇中文侧就没切换行** ⇒ 重跑脚本（幂等）即补；
  ⑤ **我自己造成的**：批量去链接时**误删了锚点链接**（同一标题两种语言 anchor 必然不同）⇒ 恢复并加锚点豁免。
  **"补了译文"必须紧接着"重跑生成脚本"**，否则中文侧缺一行加注。
- **与核对二的耦合**：`核对二` 必须带 `-PairDir`（见上），否则临时目录里没有英文兄弟、切换行不插，会**误报**副本被手工改过。

## 双向自证：判据自己也要能被检验

**只验一头＝半条判据**（假通过＝只验了好样本；**假红**＝只验了坏样本）。五道各跑两头：

| 判据 | 已知**坏**样本 ⇒ 必红 | 已知**好**样本 ⇒ 必绿 |
|---|---|---|
| 核对一 | 安装版任一文件**末尾加一个空格**；或把任一文件**改名**（缺文件路径） | 复原后重跑 |
| 核对二 | 在 `resources\` 任一副本里**手工改一个字**；或改源后**不重跑脚本** | 重跑脚本刷新后 |
| 核对三 | 往任一副本里**塞进一个禁用词** | 重新生成后 |
| 核对四 | 新增一个含 `[](不存在的文件.md)` 的临时文件；或把 `$root` 指向空目录（下限） | 删掉临时文件后 |
| 核对译本 | 改英文侧内容**不重新记录**（哈希红）；或删掉英文侧一个标题后**重新记录**（结构签名红）；或把英文侧链接指回中文件 | 复原后重跑 `-Write` |

> **能报"干净"的检查，必须先证明它会报"脏"。**
> 反向同样成立：**会报"脏"的检查，也必须证明它对干净输入不报"脏"**——
> 否则它报出的问题**根本不存在**。本机实测过两次假红，两种根因都值得记住：
>
> 1. **变量名大小写不敏感**：脚本里写了 `$i` 与 `$I`，其实是同一个变量，报出 **10 个假差异**。
> 2. **编码**：本机是 **Windows PowerShell 5.1**，`Get-Content` **不带 `-Encoding UTF8`** 时按 **GBK** 解码中文，
>    **多字节序列会把换行符一起吞掉**——同一文件数出 **110 行**，真值 **199 行**
>    （用 `[System.IO.File]::ReadAllLines()` 或带 `-Encoding UTF8` 才对）。
>    **同理：含中文的 `.ps1` 脚本若不带 UTF-8 BOM，会被按 GBK 读成乱码而解析失败。**
>    **测量方法本身就是一条判据，它也会骗人。**
> 3. **判据的适用范围写错**：译本门把"英文侧链接必须指英文译本"这条规则**也套到了语言切换行**上，
>    而切换行**按定义**就指中文侧 ⇒ 每篇必报一条假红。**修法是明确豁免这一类，不是放宽整条规则**
>    （放宽＝连真问题一起放过）。同年同月的第四例是**复算的输入没固定住**：
>    生成脚本按"目标目录里有没有英文兄弟"决定插不插切换行，于是 `核对二` 在临时目录复算时**输入不同、输出少一行**，
>    把"副本被手工改过"**误报**成真缺陷 ⇒ 修法是新增 `-PairDir`，把**判定输入与输出目录分开**。
>    **"可复算"必须连输入一起固定**。

## 审查通道（给别的实体：怎么审这套核对）

**写判据的人不审自己。** 复核只需三问，全部有落点：

| 审查三问 | 落点 |
|---|---|
| ① 这条判据**能不能失败**？ | 上节"已知坏样本"那一列——**照做**，看它是否真的红 |
| ② 它**不覆盖什么**？ | 各条下的"**不覆盖**"＋上节总述；**没写就是没写** |
| ③ **证据在哪**？ | 命令里的"证据：…"行 ＋ **项目侧核对记录**里对应的那一行 |

### 跑不了命令时的**等价复核协议**（重要）

**为什么必须写这一条**：本轮的独立复核者**全部**因沙箱无法执行命令，
如果通道只写"跑命令"，"交给别的实体审"就会退化成**没人能审**。不能跑命令时：

| 步骤 | 做什么（只用读／列目录／搜文本） | 记什么 |
|---|---|---|
| 1 | 列出两侧**文件全集**（含名字与行数） | 两侧文件数；多出／缺少的名字 |
| 2 | 逐对读：比**首行**、**行数**、**末行**，再各抽 3 段中段（**行数必须用 `-Encoding UTF8` 或 `ReadAllLines` 量**） | 行数是否相同；抽段是否一致 |
| 3 | 逐条**链接**：取目标路径，确认目标文件存在 | 链接条数；断链条数 |
| 4 | 逐条**出处（文字指针）**：回原文搜标题／句子 | 支持／找不到；**找不到的写"无法回核"** |
| 5 | **搜禁用词**：在副本里搜工程名等 | 命中数（须为 0） |

**降级规则（必须照写）**：清单点验**能**发现文件缺失、行数不符、链接指空、禁用词残留；
**不能**发现"行数相同但内容被替换"（那是哈希级）。
所以它的结论上限是「**未发现差异（未做哈希级验证）**」，
**不许写成"逐字相同"**，也不许写 `OK: N files identical`——**没跑过的结论不许用跑过的话说。**

> **复核者也是被审对象**：复核结论同样要过三问。本轮就发生过复核者**声称"全库零命中"**、
> 而那条短语其实在原文里存在；也发生过复核者说某两处章节号**不存在**、实际**都存在**。
> **照复核者的话直接改，会把对的改成错的**——先自己复现一遍。

### 记录留在项目里，不进技能

| 项 | 归属 | 说明 |
|---|---|---|
| **方法、格式、判据、审查三问、等价复核协议** | **技能**（本文件） | 跨项目复用，不含项目信息 |
| **运行记录、复核登记、冲突结论** | **项目侧** | 每个项目**各记一份，互不混写** |
| **脱敏规则与生成脚本** | **源项目侧**（不进技能） | 它按定义含真名，放进技能包就自我否定 |

**记录文件名由那个项目自定**（**不是通用规则**），放在项目侧、与可复用件分开即可。

**项目侧记录建议格式**：

```markdown
| 时间 | 判据 | 范围 | 结果 | 未覆盖 | 执行者 | 证据 | 复跑 |
|---|---|---|---|---|---|---|---|
```

**反悔通道**：你复核后结论与我不同，**在项目侧记录里追加你自己的一行**（**不要改我的行**），
写上你跑的命令与输出。冲突处置顺序：
**能复现的一方优先 ＞ 两边都能复现则以权威源为准 ＞ 都复现不了取保守解释并标"已知未解"**。

## 换机器 / 换工程

| 场景 | 要做什么 |
|---|---|
| **换机器**（同一个项目） | 整目录复制到 `%USERPROFILE%\.agents\skills\`；跑**核对一** |
| **换工程**（只带走这个技能目录） | **核对二、三没有对象**（没有本机的源与生成脚本）：①以 `SKILL.md` 为准（"以系列正文为准"对你也没有对象）②核对四把 `$root` 指向**你的**项目树 ③`$floor` 按规模重定 ④记录放**你的**项目侧 |

> **一句话**：核对判的是**两个具体路径之间的关系**，不是一个绝对的"正确"。
> 路径换了，判据必须重新指对象——**判据没有对象时，它给的"OK"是假的。**
