# 05 · 验证与防假通过：怎么知道真的改对了

[English](05-验证与假通过.en.md) | 中文

> 本篇是三层之外的**横切面**——它把某工程设计层 §九（验证与交付纪律）与操作层 §4、§11（几十条实测教训）里
> 关于"**什么算通过**"的部分收拢成一份可执行的清单。
>
> 这一篇值得单独读，因为某工程最贵的一类损失不是"没做"，而是**"以为做对了"**。

## 一、"通过"的定义：三态

**每次汇报结果，只有三种状态，且不许混写：**

> **术语纪律**：本系列**不加限定词地写"三态"时，一律指这一条（证据三态：已验证／未验证／已知未解）**。
> 别处的"三态"必须带限定词——如 [01 §二](01-协作的基本盘.md) 的"**裁定的**三态"、
> [03 §4.1](03-工程原则.md) **实例里第 4 层**的"**三态**"（允许／显式拒绝／沿用上层）——否则同一个词就有了多个所指（[06 §一](06-事故台账与断点恢复.md) 第 14 条就是这个代价）。

| 状态 | 含义 | 写法要求 |
|---|---|---|
| **已验证** | 跑过，有判据 | 必须附**命令 ＋ 输出**；只写"已验证"不算 |
| **未验证** | 没跑，或环境不具备 | 写明**为什么**不具备（如无桌面会话 ⇒ 观感无法验） |
| **已知未解** | 知道有问题，暂时没解 | 如实登记，不许当已解决 |

**三条硬禁令**：

- 「**合理未验证**」≠「通过」。
- 「**预期会通过**」不许写成「已完成」。
- **跳过项（SKIP）不是通过**——某工程明确记录"SKIP 不是通过"，且跳过必须走**独立退出码**，
  不许用更宽松的断言替换原来的断言组。

**为什么**：`docs/01 §九.2` 的原话逻辑是——**自检的价值等于"它失败时你是否相信它"**。
一旦你允许"未验证"混进"通过"，整套判据的可信度就归零了。

**出处**：`工程根的 README.md` 红线；`docs/01 §九.2`；`docs/00 §11.1`。

## 二、假通过的六种形态

**"假通过"是本篇的核心概念：判据跑完了、显示绿了，但什么都没验到。**

| 形态 | 具体样子 | 堵法 |
|---|---|---|
| **恒真断言** | 断言条件永远成立（`|| true`、把常量真值当结果、`check(…, true)`） | 自问：**"如果代码变回改之前，它会不会红？"** 不会红的就是恒真断言，**等于没写** |
| **测了不该测的** | 用"语句没报错"代替"行为被拒"：某数据库在"0 行受影响"时**不触发**前置触发器 ⇒ 判据必然通过 | 断言**结果**，不是"没报错"；判据要能构造出**必然失败**的输入 |
| **跳过被当通过** | 清理阶段的异常被吞（只打印不判失败）；环境不具备时整段 SKIP 仍退出 0 | 清理块失败必须走断言；跳过走独立退出码；**"通过项数变少"与失败同级** |
| **扫描下限缺失** | "0 个违规"其实是因为**一个文件都没读到** | 判据必须带扫描下限：**"0 命中"不能建立在"没读到"上** |
| **报告了缺陷仍退出 0** | 脚本打印【缺陷】却返回成功 ⇒ 在闸门眼里与通过无异 | **打印缺陷的脚本必须把缺陷计入退出码**；输出可解析的结果行 |
| **探针静默** | 探针启动失败、零输出、退出 0——**最像通过的一种** | 探针分阶段打印 ＋ 退出追踪 ＋ 超时兜底；**"一条断言都没跑"不算通过** |

**出处**：`docs/00 §4.3`、`§11.1`、`§11.2`、`§11.4`、`§11.14`；`docs/01 §九.1`；`证据/S4_裁定落实.md`。

**反向还要防"假红"**：判据自己写错（循环变量被覆盖、计数错、路径拼接错）会报出一串**并不存在**的问题。
假红本身不产生隐患，但它**吃掉信任**——一处假红之后，真红也容易被当成假红放过。
处置见 [02 §五](02-动手的纪律.md)：**两条独立证据互相矛盾时，先查判据。**

## 三、判据设计的七条硬要求

1. **能失败**：写判据时自问"代码改回去它会不会红"；答不出来就删。
   配**负例控制**——构造一个"改动前"的样本，判据必须红。
   > 某工程的原话：**能报"干净"的检查，必须先证明它会报"脏"。**
   > 实例：扫描器第一次用了"顶格的函数声明"这个正则，而两份重复实现都缩进两格 ⇒ 报"0 个"——**假清白**。
2. **绑行为，不绑载体**：断言绑"链接指向哪、是否禁用、提交体是什么形状、几何多大"，
   **不绑"当时恰好承载它的那个类名或那段文案"**——载体是**会随重构消失**的。
   某工程实测踩过 4 次：断言绑的载体被删掉后，`indexOf(...) < 0` 这类判据**由真变恒真**，却看着还在守。
3. **期望值从事实派生**：能算出来的期望，就不要写字符串字面量。
   某工程一天内三次同族假红，根子都是**"期望值被手抄了一份副本"**（钉死调用字面、凭空写期望顺序、
   手抄改名前夹具的旧值）。失败提示必须**同时打"期望"与"实测"**，否则红了也判不出是谁的错。
4. **只钉性质，不钉字面**：实现合法改形就假红，说明钉过头；但**只放宽字面、不放宽性质**。
   ⚠ 反例纪律：把"每级至少差 1px"偷偷改成"大于 0"，那不是修判据，是**用恰好能被满足的断言把问题洗白**。
5. **随事实生长**：判据不要钉住当天的快照（如"删除钮共 N 个"）——正确的新增会被误判成回归。
   用"**不增长**"这类相对口径代替绝对数字。
6. **有效优先于形式**：判据要能**区分对与错**，而不是只证明"跑过了"。
   一条能区分的判据胜过十条恒真断言；**"跑了一个检查"不等于"查过"**。
   ⚠ 表面验证的三种典型：**只报 OK／FAIL 不给证据**、**只数个数不看内容**、**把"没报错"当"对了"**。
   它们共同的特征是——**判据的结论无法被第二个人复核**。
7. **判据必须交给别人审**：每条判据旁边写清**三样**（缺一样就不算"有判据"）——
   ①**如何复核我**：一条能直接跑的复跑命令 ＋ 预期输出；
   ②**我不覆盖什么**：有效边界；
   ③**本次运行的证据**：扫了多少、比了哪些、原始输出。
   没有这三样，绿灯只是**写判据的人自己相信自己**。

**出处**：`docs/00 §4.3`、`§4.4`、`§11.31`、`§11.32`、`§11.33`、`§A.2`；`docs/02 §三.1b`、`§三.15`。
第 6、7 条与下面那张表是**本轮增补**（来源：一次真实的假红——检查脚本变量名大小写不敏感，报出 10 个不存在的差异），
**某工程原文没有这三条**，属本系列的推断。

### 判据自身的三条自证义务（通道 ＋ 方法指引）

| 义务 | 具体做法（缺一条就不算"有判据"） |
|---|---|
| **双向自证** | 一个**已知好**的样本 ⇒ 必须绿；一个**已知坏**的样本 ⇒ 必须红。**只验一头＝半条判据**（假红与假通过正是各自验一头的结果） |
| **写明边界** | 一句话讲清**它不覆盖什么**（例："只判逐字节相同，不判内容对错，也不判链接与锚点"）。**没写边界的绿灯会被当成全覆盖保证** |
| **留证据与通道** | 运行要留下**中间证据**（扫到的数量、比对清单、原始输出），并给别的实体一条**自己能重跑**的命令。记录**留在项目里，不随可复用件分发**（[07 §四.6](07-文档体系与长期接手.md)） |

**为什么单列**：一条**只会报 OK** 的检查比没有检查更危险——它给人"已经查过"的错觉（正是 §二 假通过的土壤）。
**判据的失效方式，必须写在判据旁边。**

**审查权属于别的实体**：写判据的人**不能同时是唯一审它的人**——把上面三样**交出去**
（提交、写进文档、贴进汇报），别人才可能"看着你的判据"复核，而不是只能信你的结论。
**"互相协作减少隐患"靠的是判据可被接手，不是靠彼此信任。**

## 四、分层验证：什么在哪一层测

| 种类 | 在哪测 | 为什么 |
|---|---|---|
| 纯逻辑、选择语义 | 自建桩（如 Node） | 快、可复跑、适合 CI |
| **渲染与交互** | **真实浏览器** | Node 里自写的假 DOM 会给出误报（某工程因此得到 8 条误报） |
| 数据末态 | 真实库 | 但**只判"不增长"**，禁用绝对行数 |
| 授权 | 真实服务 + **无权限账号发起** | 低权限身份看元数据会得到**假的"没有"** |

**两条具体纪律**：

- **库末态禁用绝对行数**：用户会真实新建数据，绝对行数会让一批脚本集体误报。
  只允许①按本次自造数据的标识定向 ②**前后不增长**。
- **"我跑不了" ≠ "可以不跑"**：环境不具备就**显式标未验证**，并让有执行条件的一方**立刻代跑**可达的闸门
  （语法检查、进程=磁盘），不要把整批写完再交。

**出处**：`docs/00 §4.4`（库末态只判"不增长"）、`§4.5`（渲染类断言放真实浏览器）、`§4.6`、`§11.15`、`§11.8`。

## 五、探针必须自证可信

探针（诊断脚本、一次性核查脚本）是"**用来判真假的东西**"——它自己不可信，给出的就是假结论。
某工程记录过探针自身不可信的多种情形：请求没带必要标头被拒、把列记到了错的表、自己拼清理语句留下脏数据。

**四条要求**：

1. **分阶段打印 ＋ 退出追踪 ＋ 超时兜底**；"一条断言都没跑"不算通过。
2. **"样本不足"与"断言失败"必须分开**：前提不具备走"跳过"（独立退出码），
   **只有"元素在、性质不成立"才判失败**。
   > **假失败与假通过一样有害**——它会把你从真问题上引开。
3. **选样本要选"能体现该性质"的样本**：用"第一张卡片"当样本，而那张卡片恰好没有可验证的内容，
   会让 4 条断言恒假失败。样本要先用查询证明它确实具备被断言的性质，**并把样本打印出来**。
4. **探针不许碰真数据**：破坏性路径先声明；清理走工程里那份统一的实现，**探针不许自己拼删除语句**。

**出处**：`docs/00 §11.4`、`§11.5`、`§11.14`、`§11.26`、`§11.3`。

## 六、从"现象"到"结论"的纪律

1. **先停手，再定位**：不要在"看起来快好了"的心态下继续叠加改动；先把现象固定成一条**可复现的最小路径**。
2. **归因靠探针，不靠直觉**：**现象相同 ≠ 机制相同**。动手前问"这个现象还有哪种解释？"，
   做**能区分两种解释的最小探针**，打在真实服务上，覆盖"改之前 / 改之后"。
3. **复现不出用户报的错时，不要继续加猜**：直接向用户要**控制台整条报错（含状态码）＋ 确切操作路径**。
4. **两个高频误判**：①"代码改了但行为不对" → 先查**进程是不是旧代码**；
   ②"断言红了" → 先查**断言的前提在这个上下文里成立吗**。
5. **修复后回看修复本身**：逐条问"我改的是**因**还是**症**？"命中补丁特征（枚举硬编码换空间、
  同一属性多处重复、没定位成因就动参数、仓里已有正确范式却没用）⇒ **当场重构，不许"留着以后"**。

**出处**：`docs/00 §8.1`、`§8.2`、`§8.2b`；`docs/01 §九.5`。

## 七、给自然人的一页检查表

AI 报"做完/通过"时，逐条对：

- [ ] 有没有给出**命令与输出**？（只有结论＝未验证）
- [ ] 通过数是**上升**还是下降？跳过项有几条、为什么跳过？
- [ ] 判据**改过**吗？如果改过，是"只放宽字面"还是**连性质一起放宽**了？
- [ ] 这次报的"通过"，覆盖的是**用户会走的那条路**吗？
      （某工程的高危缺陷正长在这里：各处断言都对，**合起来的那条用户路径没人走**）
- [ ] 有没有**明确列出未验证的部分**？（尤其是只能目视的观感类）
- [ ] 涉及数据的验证，用的是**自造数据**吗？临时数据清了吗？
- [ ] 有没有"先跑一遍再说"的痕迹？（修改后立刻跑语法闸门，而不是三分钟后）
