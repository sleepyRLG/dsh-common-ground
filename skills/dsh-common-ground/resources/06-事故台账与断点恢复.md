### 症状 → 编号（反查）

**人是按症状进入的，不是按编号**。出问题时从这一列找起：

| 你看到的现象 | 先查 |
|---|---|
| 源码中文乱码、行数变少、语法错误 | **#1** |
| "代码改了但行为不对" | **#2** |
| 闸门全绿，但页面坏了 | **#5 #6 #9** |
| 断言红了，查代码却查不出问题 | **#8 #10** |
| 数据莫名少了，或日期差一天／时区不对 | **#3 #4 #15** |

## 二、从事故里抽出的六个"通用形状"

1. **"各自都对，合起来错"**：每处断言都过，但用户会走的那条路径没人测。
   ⇒ 关键路径要有一条**端到端**判据。
2. **"造出来了 ≠ 用得上"**：功能写着、接口通着，但**没有任何入口／没有权限／没有登记**
   ⇒ 交付时必须回答"用户怎么走到它"。
3. **"修复动作本身是新缺陷来源"**：一次修一行，带走了同一行的其它旗标。
   ⇒ 替换前断言命中数；改完看**连带**（哪些看起来无关的检查变红了）。
4. **"唯一事实源被常规动作毁掉"**：号称幂等的脚本把别人那节删了。
   ⇒ 脚本要能自守，别把正确性寄托在"大家都会小心"。
5. **"验证环境的版本不自证"**：改了代码、验的却是旧进程。
   ⇒ 让环境自己报指纹。
6. **"注释在说反话"**：一句错注释把整类缺陷判成"不是洞"。
   ⇒ 判定要引到**具体行号**，注释与口头结论都不算证据；发现自己写的注释与代码相反，**立刻改注释**。

## 三、断点：可索引、可复原

**规矩**：
1. **避免制造非必要断点**——一件事**一次做完**（改码 ＋ 判据同步 ＋ 闸门绿 ＋ 入账），不要留一半；
2. **避免遗漏**——一次改动的**全部连带走点**（判据、文案、列宽、白名单、文档）在动手前**列全**；
3. **必须中断时**：把断点写进台账，保证**可被索引发现**、**易于还原**（写明落点与复原步骤）。

**原话**：**回滚可以发生，断点不得失踪。**

**为什么**：某工程一日之内出现过多次"改到一半回滚"（判据未同步、切片切错、锚点含空格）。
回滚本身是对的（**红灯不入账**），但若不把断点写进台账，下一轮就要**重新勘一遍**，时间被重复烧掉。

**断点台账的最小字段**：编号 · 状态 · 落点（文件:行 / 函数 / 提交）· 复原步骤 · 依据。
**纪律**：任何"打算留到下一轮"的事，**当轮**就要在台账里出现一行。

**出处**：`docs/00 §A.7`；`docs/25_断点台账.md`。

## 四、可回退：小步 ＋ 标记 ＋ 逐刀账目

- **每到一个可回退的整点，打一个标记 ＋ 导出存档包**（含库转储），并把账写在仓库里 ⇒
  "哪一版能回到什么状态"永远查得到。
- **标记一经打出不再移动**：回退＝检出标记，**不改标记**。
- **红灯即回滚，不许把红灯当一刀入账**。
- **结论与已落的刀冲突时，逐标记回退，而不是辩护**。

**为什么值得制度化**：有了它，"改错了"就只是一次可撤销的操作；
没有它，改错就会变成"要不要再赌一次"的争论。某工程的原话是"逐标签回退，代价很小"。

**出处**：`证据\存档记录.md`；`docs/21_单一实现审计与修正计划.md`。

## 五、恢复演练：备份不算备份，能恢复才算

某工程在这方面留下一批**恢复演练记录**（同一环境的多次演练，含一次被标为"作废·假通过"的记录）。
两条经验：

1. **演练要判"结果"，不是判"没报错"**：恢复到什么程度，要**逐项比对**（表数、行数、关键取值），
   而不是看脚本有没有抛异常。
2. **发现演练是假通过，就把那次记录标为作废**并留在原地，而不是悄悄删掉——
   否则下一轮会拿它当"已验证"。

**出处**：`旧案\实现\证据\演练\`（10 份 `恢复演练_20260915_*.md`）、
`旧案\实现\证据\作废\README.md` 与同目录的 `恢复演练_20260915_140850_作废_假通过.md`
（**逐字位置**：`作废\README.md` 第 7 行记载该次演练属"假通过"）。

## 六、工程被中断后，怎么接上

**最小可用的恢复入口**（某工程写成一份"重启后唯一入口"文档，包含）：

1. **本轮快照**：最新提交、标记、闸门数字、存档包位置。
2. **恢复步骤**：按序编号，每一步都有可执行的命令（含"自证"一步：跑一个脚本证明环境真的起来了）。
3. **现成的复验现场**：数据在哪、样板项目叫什么、用什么账号登录。
4. **边界**：哪些是已知的、哪些这版还不能验的。

**两条硬要求**：

- 恢复步骤里的**每一步都要能被验证**（跑完得到什么输出）；
- **换了会话语境变了**（临时区、隔离实例会消失）⇒ 环境类信息要写清"为什么会没了、怎么重建"。

**出处**：`docs/23_交接_重启后继续推进.md`；`docs/09_本地运行服务器.md`；`证据\S4.5_断点与恢复.md`。
