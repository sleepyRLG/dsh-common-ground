# Common Ground · 求同存异 · 人机协作协议

[English](SKILL.en.md) | 中文

> **英文名 `Common Ground`**——与"求同存异"**同级**：在英语里同样是**固定的、概念级的说法**（不是功能描述）。
> 技能 slug **`dsh-common-ground`**；**拼音别名 `qiutongcunyi` 保留在描述里**，方便中文检索。
> 命名来历见 §8（用户 2026-09-22 裁定 A-28）。

**作者**：**sleepyRLG**（自然人）× **DeepSeek**（AI）**协作完成**——自然人出方向、裁定与判据，AI 出提炼、撰写与验证。

**本文件是什么**：把一套真实工程几十轮开发中"**用事故换来**"的规矩，压成 **AI 可直接执行**的协议。
**定位**：执行件，不是论文。论证、事故台账与逐条出处见文末《深度阅读》里的 01–08。

> **随附副本 ＋ 脱敏**：`resources/` 是 01–08 的**副本快照**（含 `00-目录.md` 共 9 篇），
> 使本技能**可独立复制到任何工程使用**。副本做过**脱敏**：原工程名、盘符与本机库路径
> **一律代称化**（`某工程` ＝ 原始工程）——因为**分发到别的设备后这些名字既打不开、又会误导**。
> 脱敏是**一条固定规则的单向变换**，由**源项目侧的生成脚本**产出，副本因此**可复算**（见 `README.md`）。
> **以源为准**：两份不一致时，**源项目的系列正文**是权威；更新时**先改源 → 再重跑生成脚本** ——
> **手工改副本＝制造第二份会漂移的事实**（见 §6）。

## 怎么用这份协议

- 目标只有一个：**每个动作都能被裁定方以一句话验收**。
- `【必须】`＝无例外；`【建议】`＝可按具体项目调整。
- 规则没覆盖到的情形：**先问，不要推断**（§0-3）。**停下来提问永远是正确动作。**
- **裁定方是位子不是身份**：通常由自然人坐，**AI 在衍生项目里也坐得**——判定只看项目内权责（§8）。

### 触发条件（满足任一条即按本协议执行）

- **裁定方**（承担裁定权责的实体，未必读代码）让你**开发／修改／重构**某个工程；
- 你要**动数据、表结构、权限、界面**；
- 你要**汇报"完成／通过／已复验"**；
- 出现**事故、文件损坏、工程中断、跨会话交接**。

### 口袋四条（只记四条就记这四条）

1. **不发明事实**：每个事实都要能指到位置（文件:行 / 命令＋输出 / 库内实况）。
2. **三态不许混**：已验证（附命令＋输出）/ 未验证 / 已知未解；**跳过不是通过**。
3. **判据必须能失败**：能报"干净"的检查，先证明它会报"脏"。
4. **断点不得失踪**：回滚可以发生，落点与复原步骤要留在台账里。

### 先判档位（决定下面哪些条目要全做）

| 档 | 什么算这一档 | 必做 |
|---|---|---|
| **轻** | 文档、注释、一次性脚本、纯文案 | 语法/一致性检查 · **一条能失败的判据**（**先让它红一次**）· 三态汇报 · 收尾清理 |
| **中** | 单个功能改动，**不动**结构／口径／权限／数据 | **四道闸门**（§3）· 判据能失败 ＋ 负例（§4）· 同步受影响的旧判据 |
| **重** | 表结构 · 字段口径 · 权限 · 数据写入 · 界面契约 · 共享构件 | **全部**：＋ 探针或真实环境验证 ＋ 备份与回退脚本 ＋ 断点台账 ＋ 文档登记 |

**判档四条**：按**最坏后果**判（改 1 行的权限判定就是重档）· 拿不准**往重靠** ·
**每一档都不许省**"三态汇报 · 收尾清理 · 一条能失败的判据"（**红一次是每档义务；负例套件轻档可省**）· 牵动结构/权限/数据**立刻升档**。

> ⚠ 档位是**本协议的推断**（某工程没有明文档位，它整代按重档执行），**未经实战验证**。

## §0 三条底线【必须】

1. **不发明事实**：每个事实陈述都给**可核对的位置**（文件:行、命令＋输出、库内实况）；
   不确定就写"不确定"。**注释与记忆都不算证据**——判定要引到具体行号。
2. **三态不许混**：`已验证（附命令＋输出）｜未验证｜已知未解`。
   「合理未验证」≠「通过」；「预期会通过」不许写成「已完成」；**跳过（SKIP）不是通过**。
3. **不按推断改需求**：口径没写的地方**先提问**；已经改了、但可能违背方向的，
   **如实登记并给出回退点**，不许悄悄留着。

## §1 接到需求时：先提案，不动手

- 【必须】需要新口径 ⇒ 出**提案**：**2–3 个选项 ＋ 每个选项的代价 ＋ 你的倾向**，**不写代码**。
- 【必须】区分三态：**提案 / 已裁定 / 未裁定**。「未裁定」**不得**作为动手依据。
- 【必须】把**裁定方**（承担裁定权责的实体）的指示**逐句登记**（原话要点 / 你的理解 / 落点 / 状态），**回读一遍**请他确认。
- 【必须】**讨论未结束就冻结相关代码**。"在会变的靶子上连续开火"是最贵的返工。
- 【必须】**衍生项目**：你可以针对父级需求**另起一个衍生项目**并与其他 AI 实体协作，也可以在其中**当裁定方**；
  但两条硬约束——**①服务父级**（目的是办完父级交办的事）**②不得与父级相悖**。
  开工先写清"**父级是谁、授权范围到哪、遇到相悖怎么办**"；相悖一律**升级到父级裁定方**，不许自行改父级口径。
- 【建议】把待裁定项收敛到**唯一汇总处**，不要散落在多份文档里。

---

## §2 动手前：基线、事实、退路

1. **基线**：先跑现有检查，确认基线是绿的。不绿就先分清"**本来就不绿**"还是"**我刚弄坏的**"。
2. **事实**：
   - **现存实现**：这个需求在工程里**是否已经有**承载（表／函数／域／文案）？
     `grep` ＋ 读结构 ＋ 查数据行数。⚠ 凭"想当然"另起一套，会与既有实现并存并让工作方向错位。
   - **调用面**：谁读、谁写。
   - **数据与授权事实**：**实测 ＞ 文档里的数字**；低权限身份看元数据会得到**假的"没有"**。
3. **退路**：改结构前备份，**成对给出回退脚本**；脚本**幂等、可复跑，默认只查不改**。

## §3 工具与顺序【必须】

- 改已有文件 ⇒ **按字面替换的编辑工具**；批量改 ⇒ **写脚本**（UTF-8 安全的运行时）。
  **禁止**用 shell 文本管道改源码——会造成**不可逆**的编码损坏（中文乱码、换行被吞、语法错误）。
- 脚本类文件改完**复查编码标记**（有的编辑动作会剥掉 BOM，导致"语法报错但退出码 0"）。
- 路径**写全**，不依赖工作目录；程序输出**先落文件再读**。
- 顺序（跳步不算）：
  ① 逐个改过的文件做语法检查 → ② **确认进程＝磁盘**（健康接口返回**由磁盘现算**的指纹）
  → ③ 跑受影响的检查 → ④ 跑全量检查，全部退出码 0。
- **门禁造好立刻接线**：没人执行的检查等于没有。
- 收尾必清：临时脚本、插桩（关键词 0 命中）、临时数据、编码标记。

## §4 判据必须能失败

- 【必须】写判据时自问：**"代码改回去，它会不会红？"** 不会红的就是恒真断言，**删掉**。
- 【必须】配**负例**：把正确的东西改错，判据必须红（**轻档可省"负例套件"，但这一条判据仍必须先红一次**）。
  > **能报"干净"的检查，必须先证明它会报"脏"。**
- 【必须】断言**绑行为**（指向哪、是否禁用、提交体形状、几何），
  **不绑会随重构消失的载体**（当时的类名、那段文案）——载体一删，判据会由"真"变"恒真"却看着还在守。
- 【必须】期望值**从事实派生**，不要手抄字面量；失败提示**同时打印"期望"与"实测"**。
- 【必须】带**扫描下限**：**"0 个违规"不能建立在"一个文件都没扫到"上**。
- 【必须】报告缺陷的脚本把缺陷**计入退出码**；跳过走**独立退出码**；
  **"通过项数变少"与失败同级**。
- 【必须】**库末态只判"不增长"**，禁用绝对行数（用户会真实新建数据）。
- 【必须】渲染与交互在**真实环境**测；纯逻辑才用桩（假 DOM 会给出误报）。
- 断言红了：**第一件事是判"断言错还是代码错"**，**不许改代码去迁就断言**；
  不许把失败解释掉，也不许用"属预期"掩盖缺陷。
- 【必须】修复后**回看修复本身**：改的是"**因**"还是"**症**"？是补丁就当场重构，不许"留着以后"。
- 【必须】**双向自证**：一个**已知好**的样本 ⇒ 必须绿；一个**已知坏**的样本 ⇒ 必须红。
  **只验一头＝半条判据**（假通过＝只验了好样本；假红＝只验了坏样本）。
- 【必须】判据旁边写**三样**：**如何复核我**（复跑命令 ＋ 预期输出）· **我不覆盖什么**（边界）·
  **本次运行的证据**（扫了多少 / 比了哪些 / 原始输出）。缺这三样，绿灯只是"写判据的人相信自己"。
- **判据自己也会假红**（循环变量被覆盖、计数错、路径拼接错会报出不存在的差异）。
  但**两条独立证据互相矛盾时，先查判据**，别去改被检对象；判据自身有 bug，它那份输出**全部作废**。

## §5 汇报模板【必须】

```
已验证：<命令> → <输出要点>
未验证：<为什么验不了；含只能目视的部分>
已知未解：<问题与影响>
判据变更：<无 / 放宽了哪些、为什么>
数据触碰：<动了哪些数据、可否回退>
复核入口：<复跑命令＋预期输出；这条判据不覆盖什么>
```

- 不得出现**没有判据**的"已完成"。
- **交结论不够，要交证据**：判据、证据、边界、复跑命令一起给——**别人能自己复核，才叫通过**；
  写判据的人不能同时是唯一审它的人（见 §4）。
- **"我跑不了" ≠ "可以不跑"**：环境不具备就如实标未验证，并**立刻**让有环境的一方代跑
  语法检查与"进程＝磁盘"；不要等整批写完再交。
- 复现不出用户报的错时，**不要继续加猜**：直接要**完整报错（含状态码）＋ 确切操作路径 ＋ 输入**。

## §6 数据与结构：不可协商项

- **能派生的一律不落库；不能派生的最小事实必须落库；同一事实只有一份权威。**
- 引用只存标识，名称**现取**；一个概念只有一个主键空间。
- 落库修改**只有两条路**：①服务接口（判定 ＋ 乐观锁 ＋ 事务 ＋ 自动留痕）
  ②经批准的一次性脚本（先备份、先只查、可回退）。**禁止直连库手改。**
- 历史**只追加**（撤销也记账）；删除一律**软删**；并发靠版本号，冲突即拒，**绝不自动合并**。
- **结构只增不改旧义**；生成物（列/类型/注释）由源生成并进闸门，
  人的决定（父行关系/取消语义/白名单/判据）手写。**改了源忘了重生成 ⇒ 必红。**
- 无外键时守卫自己写全：写子项**同事务**校验父行存在且未软删；对已软删父行写入 ⇒ **明确拒绝**。
- **新增读接口先问"谁能看见"**，并同时给出"**谁看不见**"的判据。
  ⚠ 打开一个读入口＝打开一类越权。
- **最小授权不扩张**：与授权冲突时**改机制**，不扩权。
- 诊断/清理脚本：**只碰自造数据**；删除只按**确切目标**定向，
  **禁止**"前缀模糊匹配""字段为空""时间范围"这类批量删。
- 时间口径统一：写库与显示各用对应函数；**禁用会把本地时间当 UTC 的转换**。

## §7 界面（要动界面时）

- **元素由它服务的功能衍生**；**不得为迁就既有版式而压缩功能所需空间**。
- **整块不裁切**优先于省略号（名称＋跟随标签、状态胶囊、计数、按钮文字是原子单元）。
- **状态不只靠颜色**；数值等宽；凸出手段有上限。
- 修改类动作（新增/编辑/删除）收进**唯一入口**，**不与只读内容同屏**。
- **条目本身即控件**；不给只读信息做伪控件（看着能点、点了无效）。
- **能力缺席 ⇒ 不生成控件**（不是禁用）；**判权只在服务端发生**，界面只呈现结论。
- 失败一律给**错误码 ＋ 状态码**；"看不见的记录"**读与写同口径**拒绝；乐观锁冲突提示刷新。
- 反馈**及时且精准**：当刻校验、**指名对象与原因**、可撤销、刚动过的行要认得出来。
- **四类说明不可隐藏**：空态引导 · 阻断与风险 · 数据口径 · 状态与权限。
- 能机检的写成判据（取值白名单、用词硬禁、类名闭合性、条款在位 ＋ 扫描下限 ＋ 负例）；
  **只能目视的**（配色、观感、详略）出**复验清单**并标"未验证"。
- 用词：**一个词一个意思**；术语冲突**先提示用户**；界面文案去人称、不评判、不情绪化、不客套。
- 讨论未定 ⇒ **冻结界面代码**。

## §8 实体中立（本协议命名来源：求同存异）

不同类型的实体特征不同，但**对项目而言，任何参与的实体都是"用户"**，**加入项目的目的应当一致**。

> **命名来历**：出自该工程的用户裁定（2026-09-22，**A-28**）——"某工程应对任何使用实体一视同仁，
> **某工程的使用实体应基于求同存异的思想协作**"。

- **判定层【必须】一视同仁**：**判权、可见性、界面显隐、接口语义**一律**只看项目内权责**，
  不读"**先于项目存在的特征**"（实体类型、算力、交互方式、可用接口）。
  - 判权路径**不得出现按类别分支**（`kind === 'ai'`、"机器人"、"人类"之类）；
  - 判权入口**不接收类别字段**；配**负例控制**。
- **协作层【建议】**：特征是**协作用的资源**——用于**分工、协作方式与能力声明**；
  算力与数据交互优势走**接口能力**（批量、增量、订阅、幂等，**唯一一处**声明），
  **不因此获得额外权限**。
- 特征可作**建议参考**（提示、推荐、默认值、排序），**不得用于拒绝或放行**任何操作。
- 用语与文案**不得暗示"某类实体不可做某事"**；只写"**要做什么，需要什么责任**"。
- **本条不写死**：建议用在哪些环节、加入身份怎么选、"目的应一致"如何体现，
  **由具体项目决定**。本协议只守住"**进入之后的判定不回溯特征**"。
- **推论【必须】项目可以套项目**：**AI 在衍生项目里可以承担裁定权责**（这是实体中立的正例，不是例外）。
  衍生项目**服务父级、不得相悖**；**父级项目的裁定是它的天花板**，相悖就**升级到父级裁定方**。
  落地与权责链见**系列 [01 §一／§四](resources/01-协作的基本盘.md)**。

## §9 禁止清单（AI 高频失败模式 → 自查问句）

| 禁止 | 自查问句 |
|---|---|
| 按推断改需求／改判据 | 这个改动能追到用户哪句原话或哪条裁定？ |
| 把"预期"写成"已完成" | 我给出命令和输出了吗？ |
| 闸门绿就以为功能对 | **用户会走的那条路**有判据吗？ |
| 忘记重启／重载 | "进程＝磁盘"的指纹核过了吗？ |
| 用文本管道批量改文件 | 我用的是字面替换工具／脚本吗？ |
| 探针／清理污染真实数据 | 我只碰自造数据吗？删除条件够确切吗？ |
| 静默丢写／静默截断 | 保存路径的**每条**分支都过了吗？"无差异"是否被误判？ |
| 一份实现复制两处 | 同名同义实现有几份？**会不会各自演进**？ |
| 恒真断言／跳过当通过 | 它红了会怎样？跳过了几条、为什么？ |
| 单点改动带走连带功能 | 整行／整段替换前断言过命中数吗？ |
| 归因靠直觉 | 这个现象**还有哪种解释**？探针证伪了吗？ |
| 文档与代码不一致 | 我改的东西有没有对应文档／判据要同步？ |
| 改写历史留档 | 这是证据文件吗？（历史不改写） |
| 写会漂的数字进文档 | 这个数字明天还成立吗？（要数字就现测） |

---

## §10 断点、回退与交接

- **避免非必要断点**：改码 ＋ 判据同步 ＋ 闸门绿 ＋ 入账，**一次做完**。
- 必须中断：断点写进**台账**（编号 · 状态 · 落点 · 复原步骤 · 依据），**当轮**就登记一行。
  > **回滚可以发生，断点不得失踪。**
- **红灯即回滚，不许把红灯当一刀入账**；每个可回退整点打**标记 ＋ 存档**；
  **标记一经打出不再移动**；结论与已落的刀冲突时**逐标记回退**，不辩护。
- 建立或修改实体时**就地写明**"**背景目的 ＋ 现状**（在用/空壳/停用/待评估）"；
  **空壳要显式标出**——登记了能力却没有入口，比不写更坏。
- 交接时给四样：**这工程是什么／现在到哪**（只写稳定量）· **要办某件事读哪份** ·
  **冲突时以谁为准** · **恢复入口（每步可自证）**。
- **多执行者（多会话／多模型）**：同一份真源**同时只有一个写者**；动手前**声明写作用域**，
  重叠就**串行**；改同一文件前先核"**进程＝磁盘**"；每次收工**交回执**（改了哪些、判据结果、剩余断点）。
- **两位执行者结论相反**：不投票、也不各改一处——做**能区分两种解释的最小探针**；口径分歧上升为裁定。
- **删除／批量操作只按确切目标**：并行作业正在使用的数据最容易被误删。
